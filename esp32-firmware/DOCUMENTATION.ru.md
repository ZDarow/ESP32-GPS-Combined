## 1. Обзор архитектуры

### 1.1 Контекст системы

ESP32-S3 GNSS Tracker — это низкопотребляющий BLE-маяк, который принимает NMEA-предложения от GPS-приёмника u-blox NEO-7M и пересылает их на сопряжённый смартфон или ПК через Nordic UART Service (NUS). При отсутствии реального GPS-фикса внутренний симулятор генерирует синтетические NMEA-данные для тестирования.

### 1.2 Аппаратный стек

| Компонент | Спецификация |
|-----------|--------------|
| **MCU** | ESP32-S3 (Xtensa LX7, двухъядерный, 160 МГц, 16MB Flash QIO) |
| **GPS** | u-blox NEO-7M (UART1, 9600 бод, 3.3В) |
| **Питание** | 18650 Li-ion + DC-DC понижающий преобразователь |
| **BLE** | NimBLE стек (Bluetooth 5.0, LE 2M PHY) |
| **АЦП батареи** | ADC1_CH2 (GPIO2) |
| **Кнопка глубокого сна** | GPIO0 (активный LOW) |

#### Схема подключения

```
                    +-------------------+ 3.3V
                    |     ESP32-S3      |──────────────────────┐
                    |                   |                       │
                    |  GPIO17 (TX1) ─────┼──────> GPS RX        │
                    |  GPIO18 (RX1) <────┼──────< GPS TX        │
                    |                   |                       │
                    |  GPIO2 (ADC1_CH2) <──────────────────────┤
                    |                   |     Батарея 18650     │
                    |  GPIO0 (BOOT) <────┼────[Кнопка]───────────┤
                    |                   |                       │
                    +-------------------+                       │
                                                            GND ─┘

Примечание: GPIO0 подтянут к питанию через внутренний резистор.
           Кнопка замыкает GPIO0 на GND при нажатии.
```

### 1.5 Ключевые проектные решения

| Решение | Обоснование |
|----------|-------------|
| **NimBLE вместо Bluedroid** | Меньший объём памяти, лучшая производительность на ESP32-S3 |
| **BLE безопасность отключена** | Упрощает процесс соединения; не требуется сопряжение/связывание для передачи данных |
| **Слушатель GAP событий вместо callback** | `ble_gap_event_listener_register()` обеспечивает более чистую обработку множества событий |
| **Прямое использование `val_handle`** | Исключает состояние гонки, при котором callback `ble_gatts_add_svcs()` является асинхронным |
| **Разбивка на чанки** | MTU-осведомлённое разделение предотвращает переполнение ATT-пакетов |

```
├── build/                    # Артефакты сборки (генерируются)
├── sdkconfig                 # Конфигурация ESP-IDF

└── DOCUMENTATION.md          # Этот файл
```

> **Примечание:** Файл `fix4.md` содержит описание найденной ошибки в механизме доставки BLE уведомлений и применённое исправление. Ошибка была связана с неправильным использованием промежуточных дескрипторов характеристик вместо прямых `val_handle`, что приводило к состоянию гонки при асинхронной регистрации GATT. Исправление применено в `ble_nus.c`.

### 2.1 Описание модулей

#### `app_config.h`
Центральный конфигурационный заголовок, определяющий пины, скорости передачи, таймауты и BLE параметры.

| Макрос | Значение | Описание |
|--------|----------|----------|
| `GPS_UART_NUM` | `UART_NUM_1` | UART периферия для GPS |
| `GPS_UART_TX_PIN` | `17` | TX ESP32 → RX GPS |
| `GPS_UART_RX_PIN` | `18` | RX ESP32 ← TX GPS |
| `GPS_UART_BAUD` | `9600` | Скорость по умолчанию NEO-7M |
| `GPS_DATA_TIMEOUT_MS` | `5000` | Порог предупреждения об отсутствии данных |
| `GPS_RAW_DEBUG` | `1` | Включить логирование сырых байт (первые 200 байт) |
| `BATTERY_ADC_PIN` | `2` | Канал ADC1 2 |
| `DEEP_SLEEP_BTN_PIN` | `0` | Кнопка загрузки (GPIO0) |
| `BLE_DEVICE_NAME` | `"ESP32S3-GPS"` | Имя BLE устройства в рекламе |
| `BLE_ADV_INTERVAL_MS` | `500` | Интервал рекламных рассылок |
| `BLE_MTU_CHUNK_SIZE` | `20` | Размер чанка для BLE пакетов |

#### `main.c`
Точка входа приложения и оркестратор.

- **`app_main()`** — Инициализирует GPS UART, парсер NMEA, менеджер питания, АЦП батареи, BLE NUS и создаёт фоновые задачи.
- **`on_gps_line()`** — Callback, вызываемый для каждой завершённой NMEA строки. Парсит предложение и пересылает валидные фиксы через BLE.
- **`simulator_task()`** — Задача FreeRTOS, отправляющая синтетическое предложение `$GPRMC` каждую секунду при BLE-соединении и отсутствии реального фикса.

#### `gps_uart.c / .h`
UART драйвер для GPS модуля NEO-7M.

- **`gps_uart_init()`** — Конфигурирует UART1 (GPIO17/18, 9600 бод, 8N1, без управления потоком), устанавливает драйвер с RX буфером 2048 байт.
- **`gps_uart_register_callback()`** — Регистрирует callback завершения строки.
- **`gps_uart_task_start()`** — Создаёт задачу FreeRTOS `gps_uart_task`, которая непрерывно читает UART байты, собирает строки и вызывает callback.
- **Диагностика:** Подсчитывает общее количество байт, строк и NMEA предложений; логирует статистику каждые 5 секунд; предупреждает после 5 секунд отсутствия данных.

#### `nmea_parser.c / .h`
Автономный парсер NMEA предложений с поддержкой multi-GNSS префиксов.

- **Поддерживаемые предложения:** `$GPGGA`, `$GNGGA`, `$GPRMC`, `$GNRMC`, `$GPGSA`, `$GNGSA`, `$GPGSV`, `$GNGSV`, `$GPVTG`, `$GNVTG`, `$GPGLL`, `$GNGLL`
- **`nmea_parser_init()`** — Инициализирует парсер.
- **`nmea_parser_feed()`** — Парсит предложение, проверяет контрольную сумму и заполняет структуру `gnss_fix_t`.
- **`gnss_fix_t`** — Структура, содержащая: `type`, `valid`, `latitude`, `longitude`, `altitude_m`, `speed_kmh`, `course_deg`, `satellites_used`, `fix_quality`, `hdop`, `last_update_ms`.

#### `ble_nus.c / .h`
Реализация BLE Nordic UART Service с использованием NimBLE.

- **UUID сервиса:** `6E400001-B5A3-F393-E0A9-E50E24DCCA9E`
- **TX характеристика (Notify):** `6E400003-B5A3-F393-E0A9-E50E24DCCA9E` — дескриптор 16
- **RX характеристика (Write):** `6E400002-B5A3-F393-E0A9-E50E24DCCA9E` — дескриптор 19
- **Ключевые особенности:**
  - Слушатель GAP событий для CONNECT/DISCONNECT/SUBSCRIBE/MTU
  - Асинхронный GATT registration callback с разрешением дескрипторов по UUID
  - Отправка уведомлений с разбивкой на чанки (MTU-осведомлённая)
  - Автоматический перезапуск рекламы при отключении
  - Безопасность отключена (сопряжение не требуется)

#### `battery_adc.c / .h`
Простое измерение напряжения батареи.

- **`battery_adc_init()`** — Конфигурирует ADC1, канал 2 (GPIO2), 12 бит, 11dB ослабление.
- **`battery_read_voltage()`** — Возвращает напряжение в вольтах (предполагает опорное 3.3В, без калибровки делителя).

#### `power_manager.c / .h`
Утилиты управления питанием.

- **`power_manager_init()`** — Конфигурирует GPIO0 (кнопка BOOT) как вход с подтяжкой к питанию.
- **`power_enter_deep_sleep()`** — Переводит устройство в глубокий сон.

### 3.3 Предварительная настройка оборудования

Перед первой прошивкой убедитесь, что:

1. **Драйвер COM-порта установлен.** При подключении ESP32-S3 DevKitC-1 по USB Windows должен определить новый COM-порт (обычно COM5). Если драйвер не установлен, скачайте CP210x или CH340 драйвер в зависимости от чипа USB-UART на вашей плате.
2. **Boot-режим правильный.** По умолчанию ESP32-S3 загружается из flash. Убедитесь, что переключатель boot не находится в режиме загрузки (обычно это кнопка BOOT, которую нужно удерживать при подключении питания для входа в режим загрузчика).
3. **Питание стабильное.** Используйте USB-кабель для первоначальной прошивки. После тестирования можно перейти на автономное питание от батареи 18650 через DC-DC преобразователь.
4. **Проводка GPS модуля проверена.** GPS TX → GPIO18, GPS RX → GPIO17, GND → GND, 3.3V → 3.3V (если GPS питается от ESP32). При использовании внешнего питания GPS убедитесь в совместимости потенциалов (оба устройства 3.3V).

## 4. Справочник API

### 4.1 GPS UART (`gps_uart.h`)

```c
esp_err_t gps_uart_init(void);
esp_err_t gps_uart_register_callback(gps_line_callback_t cb);
esp_err_t gps_uart_task_start(void);
```

**Описание:**

- **`gps_uart_init()`** — Инициализирует UART1 с настроенной скоростью, пинами и размером буфера. Должен вызываться перед `gps_uart_task_start()`.
- **`gps_uart_register_callback(cb)`** — Регистрирует callback типа `void (*cb)(const char *line, int len)`, который вызывается для каждой завершённой NMEA строки (заканчивается на `\n`).
- **`gps_uart_task_start()`** — Создаёт задачу FreeRTOS `gps_uart_task`, которая непрерывно читает UART байты, собирает строки и вызывает зарегистрированный callback.

### 4.2 Парсер NMEA (`nmea_parser.h`)

```c
typedef enum {
    GNSS_FIX_NONE = 0,
    GNSS_FIX_2D,
    GNSS_FIX_3D
} gnss_fix_type_t;

typedef struct {
    gnss_fix_type_t type;
    bool valid;
    double latitude;
    double longitude;
    double altitude_m;
    double speed_kmh;
    double course_deg;
    uint8_t satellites_used;
    uint8_t fix_quality;
    double hdop;
    int64_t last_update_ms;
} gnss_fix_t;

void nmea_parser_init(void);
bool nmea_parser_feed(const char *sentence, int len, gnss_fix_t *out_fix);
```

**Описание:**

- **`nmea_parser_init()`** — Инициализирует парсер (логирует инициализацию).
- **`nmea_parser_feed(sentence, len, out_fix)`** — Парсит завершённое NMEA предложение. Проверяет контрольную сумму. Заполняет `out_fix` разобранными данными. Возвращает `true`, если предложение было распознано и разобрано.

**Правила парсинга:**
- `$GPGGA` / `$GNGGA`: Качество фикса, спутники, HDOP, высота, широта/долгота
- `$GPRMC` / `$GNRMC`: Статус (A=валидный), широта/долгота, скорость, курс
- `$GPGSA` / `$GNGSA`: Тип фикса (1=нет фикса, 2=2D, 3=3D), HDOP
- `$GPGSV` / `$GNGSV`: Общее количество спутников в поле зрения
- `$GPVTG` / `$GNVTG`: Скорость и курс
- `$GPGLL` / `$GNGLL`: Широта/долгота со статусом

### 4.3 BLE NUS (`ble_nus.h`)

```c
esp_err_t ble_nus_init(void);
esp_err_t ble_nus_start_advertising(void);
esp_err_t ble_nus_send_nmea(const char *nmea_str, int len);
bool ble_nus_is_connected(void);
void ble_nus_status_task(void *arg);
```

**Описание:**

- **`ble_nus_init()`** — Инициализирует NVS, NimBLE порт, конфигурацию хоста, GAP/GATT сервисы, NUS сервис, имя устройства и запускает задачу хоста NimBLE. Возвращает `ESP_OK` при успехе.
- **`ble_nus_start_advertising()`** — Запускает BLE рекламу с именем устройства `ESP32S3-GPS`, неориентированный соединяемый режим, общедоступное обнаружение. Автоматически вызывается при синхронизации стека и отключении.
- **`ble_nus_send_nmea(nmea_str, len)`** — Отправляет NMEA строку через BLE уведомления. Обрабатывает MTU-осведомлённое разбиение на чанки. Возвращает `ESP_OK` при успехе, `ESP_FAIL` если не подключён или уведомление не отправлено.
- **`ble_nus_is_connected()`** — Возвращает `true`, если BLE клиент подключён.
- **`ble_nus_status_task(arg)`** — Задача FreeRTOS, периодически проверяющая статус соединения каждые 5 секунд.

### 4.4 АЦП батареи (`battery_adc.h`)

```c
void battery_adc_init(void);
float battery_read_voltage(void);
```

**Описание:**

- **`battery_adc_init()`** — Конфигурирует ADC1, канал 2 (GPIO2), 12-битное разрешение, 11dB ослабление.
- **`battery_read_voltage()`** — Читает сырое значение АЦП и преобразует в напряжение, предполагая опорное 3.3В. **Примечание:** Не учитывает делитель напряжения — для точного измерения требуется калибровка.

#### Калибровка АЦП батареи

По умолчанию `battery_read_voltage()` возвращает напряжение, пропорциональное сырому значению АЦП с коэффициентом `3.3В / 4095`. Если между батареей и GPIO2 установлен резистивный делитель (например, для расширения диапазона измерения), необходимо внести поправочный коэффициент.

**Алгоритм калибровки:**

1. Измерьте реальное напряжение батареи мультиметром (`V_real`).
2. Запишите сырое значение АЦП (`raw_adc`) из лога или отладите код.
3. Вычислите коэффициент: `k = V_real / (raw_adc * 3.3 / 4095)`.
4. Внесите коэффициент в код:

```c
#define BATTERY_ADC_CALIBRATION_FACTOR 1.23f  // Пример значения

float battery_read_voltage(void) {
    int raw = adc1_get_raw(ADC1_CHANNEL_2);
    float voltage = (raw / 4095.0f) * 3.3f * BATTERY_ADC_CALIBRATION_FACTOR;
    return voltage;
}
```

**Рекомендуемые значения делителя:** если используется делитель 100kΩ / 100kΩ, коэффициент ≈ 2.0. Точное значение зависит от резисторов в вашей схеме.

### 5.2 Получение NMEA данных через BLE (Python / bleak)

```python
import asyncio
from bleak import BleakClient

DEVICE_ADDRESS = "7C:4F:AD:BB:E2:12"  # Замените на MAC вашего устройства
NUS_SERVICE_UUID = "6E400001-B5A3-F393-E0A9-E50E24DCCA9E"
NUS_TX_CHAR_UUID = "6E400003-B5A3-F393-E0A9-E50E24DCCA9E"

def notification_handler(sender, data):
    print(f"Получено: {data.decode('utf-8', errors='replace')}")

async def main():
    async with BleakClient(DEVICE_ADDRESS) as client:
        await client.start_notify(NUS_TX_CHAR_UUID, notification_handler)
        print("Ожидание NMEA уведомлений...")
        await asyncio.sleep(60)  # Слушаем 60 секунд

asyncio.run(main())
```

### 5.5 Кастомный NMEA симулятор

Симулятор генерирует синтетическое предложение `$GPRMC` с фиктивными координатами (Мюнхен, Германия) каждую секунду при активном BLE-соединении. Он работает независимо от наличия реальных GPS данных и служит для отладки BLE-канала при отсутствии обзора неба.

**Как изменить данные симулятора:**

Отредактируйте строку в `main.c`:

```c
            const char *fake_nmea = "$GPRMC,120000,A,4807.038,N,01131.000,E,0.0,0.0,010124,,,A*77\r\n";
```

Поля предложения:
- `120000` — UTC время (ччммсс)
- `A` — статус фикса (A=валидный, V=невалидный)
- `4807.038,N` — широта (48°07.038' N)
- `01131.000,E` — долгота (11°31.000' E)
- `0.0` — скорость (узлы)
- `0.0` — курс (градусы)
- `010124` — дата (ддммгг)
- `A*77` — режим и контрольная сумма

**Как отключить симулятор:**

Закомментируйте или удалите вызов `simulator_task()` в `app_main()`:

```c
// xTaskCreate(simulator_task, "sim", 4096, NULL, 5, NULL);
```

Или замените тело задачи на пустой цикл:

```c
while (1) {
    vTaskDelay(pdMS_TO_TICKS(1000));
}
```

**Важно:** Симулятор отправляет данные только при активном BLE-соединении (`ble_nus_is_connected() == true`). Реальные GPS фиксы пересылаются через callback `on_gps_line()` и имеют приоритет в логах.

## 6. Устранение неполадок и FAQ

### 6.1 Частые проблемы

| Проблема | Симптомы | Решение |
|----------|----------|---------|
| **Нет GPS данных** | NMEA строки отсутствуют в логе монитора | Проверьте проводку: GPS_TX → GPIO18, GPS_RX → GPIO17. Убедитесь, что скорость 9600 бод. Проверьте предупреждения `GPS_DATA_TIMEOUT_MS`. |
| **Искажённый NMEA вывод** | Некорректные символы в логе | Несоответствие скорости NEO-7M. Убедитесь, что GPS настроен на 9600 бод. |
| **BLE не виден** | Устройство не найдено в сканере | Проверьте лог сообщение `ble_nus_start_advertising()`. Проверьте `BLE_DEVICE_NAME` в `app_config.h`. |
| **Нет BLE уведомлений** | Подключено, но данные не поступают | Убедитесь, что уведомления включены на TX характеристике (CCCD = `0x0100`). Проверьте `s_tx_val_handle` в логе. |
| **`ble_gatts_notify_custom FAILED! rc=3`** | Ошибка отправки уведомления | Неверный дескриптор. Убедитесь, что `s_tx_val_handle` не равен нулю (должен быть 16). |
| **`ble_gatts_notify_custom FAILED! rc=11`** | Ошибка выделения MBUF | Увеличьте `CONFIG_BT_NIMBLE_MSYS_1_BLOCK_COUNT` или уменьшите размер чанка. |
| **Разрыв соединения после обновления MTU** | Отключение во время обновления PHY | Нормальное поведение для некоторых BLE стеков. Данные возобновляются после повторного соединения. |
| **Неточное напряжение батареи** | Неверное показание напряжения | Добавьте коэффициент калибровки делителя напряжения в `battery_read_voltage()`. |

### 6.3 Примечание по BLE безопасности

BLE безопасность (SMP) **отключена** в этом проекте (`CONFIG_BT_NIMBLE_SECURITY_ENABLE=n`). Это означает:
- Не требуется сопряжение/связывание
- Нет шифрования
- Данные передаются в открытом виде по воздуху
- Подходит для тестирования и нечувствительных приложений

Для включения безопасности измените `sdkconfig` и реализуйте callback `ble_hs_cfg.sm_io_cap`.

### 6.4 FAQ

**В: Почему симулятор работает, даже когда GPS подключён?**  
О: Симулятор работает unconditionally каждую секунду. Реальные GPS фиксы пересылаются через `on_gps_line()`. Симулятор — это запасной вариант для тестирования без обзора неба.

**В: Как изменить имя BLE устройства?**  
О: Измените `BLE_DEVICE_NAME` в `main/app_config.h` и пересоберите проект.

**В: Можно ли использовать WiFi одновременно с BLE?**  
О: Да, ESP32-S3 поддерживает совместное использование WiFi + BLE. Однако этот проект не использует WiFi.

**В: Как войти в глубокий сон?**  
О: Нажмите кнопку BOOT (GPIO0). Устройство перейдёт в глубокий сон и может быть разбужено GPIO прерыванием или таймером.

**В: Какой срок работы от батареи?**  
О: Зависит от интервала рекламы и частоты соединений. При интервале рекламы 500 мс с периодическими соединениями ожидайте несколько дней на батарее 18650.

**В: Как добавить дополнительные типы NMEA предложений?**  
О: Расширьте `nmea_parser_feed()` в `components/nmea_parser/src/nmea_parser.c` новыми блоками `strncmp` и логикой извлечения полей.

### 6.5 Известные проблемы и ограничения

| Проблема | Статус | Описание |
|----------|--------|----------|
| **Разрыв соединения при обновлении MTU** | Известная | Некоторые BLE стеки (включая WinRT/bleak) разрывают соединение во время обновления MTU. Данные возобновляются после повторного соединения. |
| **Нет энергосберегающих режимов GPS** | Ограничение | NEO-7M не переводится в режим низкого потребления. Для увеличения срока работы батареи рассмотрите использование модуля с поддержкой энергосберегающих режимов (например, NEO-6M или NEO-M8N). |
| **Нет кэширования NMEA данных** | Ограничение | При разрыве BLE соединения данные теряются. Для критичных приложений реализуйте локальное хранение в NVS или SD-карту. |
| **Один клиент BLE одновременно** | Ограничение | Текущая реализация поддерживает одно активное BLE соединение. При подключении второго клиента первое соединение будет разорвано. |
| **Нет шифрования BLE** | По проекту | BLE безопасность отключена для упрощения. Данные передаются в открытом виде. |

### 7.5 Потребление энергии

Измеренные значения тока потребления (типичные, могут варьироваться в зависимости от конфигурации):

| Режим работы | Потребление | Примечания |
|--------------|-------------|------------|
| **Глубокий сон** | ~10 µA | Минимальное потребление, пробуждение по GPIO0 |
| **BLE реклама (500 мс)** | ~1.5–2.5 mA | Периодическая рекламная рассылка |
| **BLE соединение ( idle )** | ~3–5 mA | Поддержание соединения без передачи данных |
| **BLE передача данных** | ~5–10 mA | Пиковые значения при отправке уведомлений |
| **GPS активный (NEO-7M)** | ~30–40 mA | Постоянный приём спутников |
| **Итого (пик)** | ~45–50 mA | GPS + BLE передача одновременно |

**Расчёт времени работы от батареи 18650 (2000 mAh):**

- Режим рекламы (основной): ~2000 mAh / 2 mA ≈ 1000 часов ≈ 40 суток
- Режим с активным GPS: ~2000 mAh / 35 mA ≈ 57 часов ≈ 2.4 суток
- Смешанный режим (реклама 500 мс + периодические соединения): ~5–10 суток
