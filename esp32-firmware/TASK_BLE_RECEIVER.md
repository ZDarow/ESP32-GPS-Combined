# ТЗ: BLE-приёмник NMEA на Windows 10 (этап верификации перед Android)

## 1. Цель этапа
Создать Python-приложение на Windows 10, принимающее NMEA-поток с ESP32-S3 по BLE, парсящее координаты и пишущее трек в файл. Используется для верификации протокола перед переносом логики на Android.

## 2. Зафиксированные входные данные

| Параметр | Значение |
|---|---|
| MAC устройства | `7C:4F:AD:BB:E2:12` |
| Имя устройства | `ESP32S3-GPS` |
| NUS Service UUID | `6e400001-b5a3-f393-e0a9-e50e24dcca9e` |
| TX Characteristic (Notify) | `6e400003-b5a3-f393-e0a9-e50e24dcca9e` |
| RX Characteristic (Write) | `6e400002-b5a3-f393-e0a9-e50e24dcca9e` |
| Формат данных | NMEA-0183, чанки ≤20 байт, разделитель `\r\n` |
| Частота | 1 строка/сек |
| Тестовая строка | `$GPRMC,120000,A,4807.038,N,01131.000,E,0.0,0.0,010124,,,A*77` |
| ОС | Windows 10 |
| Python | 3.14.6 |
| Каталог проекта | `C:\Users\Mi\Ublox\esp32s3-gnss-ESP-IDF\tools\ble_receiver` |

## 3. Требуемая структура файлов

```
tools/ble_receiver/
├── requirements.txt
├── config.py
├── nmea_parser.py
├── ble_client.py
├── track_logger.py
├── main.py

```

## 4. Спецификация модулей

### 4.1 requirements.txt
```
bleak>=0.22.0
```
Парсер NMEA пишется вручную, внешние зависимости не используются.

### 4.2 config.py
Константы из раздела 2. Плюс:
- `RECONNECT_DELAY = 3` (сек)
- `DATA_TIMEOUT = 10` (сек)
- `OUTPUT_DIR = "output"`

### 4.3 nmea_parser.py
- Функция `validate_checksum(sentence) -> bool`: XOR байтов между `$` и `*`, сравнение с hex.
- Функция `parse_rmc(sentence) -> dict`: широта, долгота (в градусах), скорость (км/ч), курс, UTC-время, статус валидности.
- Конвертация `DDMM.MMMM` → `DD + MM.MMMM/60`. Учёт полушарий N/S, E/W.
- Возврат `None` при невалидной строке.

### 4.4 ble_client.py
- Класс `BleNusClient` на базе `bleak`.
- Подключение по MAC.
- Подписка на TX-характеристику.
- Внутренний байтовый буфер: сборка чанков до `\r\n`, возврат полных строк.
- Автопереподключение при разрыве (задержка из config).
- Контроль таймаута данных: warning при отсутствии байт > `DATA_TIMEOUT`.

### 4.5 track_logger.py
- Запись в CSV: `local_time, utc_time, lat, lon, speed_kmh, valid`.
- Имя файла: `track_YYYYMMDD_HHMMSS.csv` в `output/`.
- Потокобезопасная дозапись.

### 4.6 main.py
- Инициализация клиента и логгера.
- Цикл: получение строки → парсинг → вывод в консоль → запись в CSV.
- Формат консольного вывода:
  ```
  [12:00:00] FIX lat=48.117300 lon=11.516667 spd=0.0 km/h A
  ```
- Корректное завершение по Ctrl+C: отписка, закрытие файла.

## 5. Порядок действий агента

1. Создать каталог и структуру файлов.
2. Создать виртуальное окружение:
   ```
   cd C:\Users\Mi\Ublox\esp32s3-gnss-ESP-IDF\tools\ble_receiver
   python -m venv .venv
   .venv\Scripts\activate
   pip install -r requirements.txt
   ```
3. Реализовать модули в порядке: `config.py` → `nmea_parser.py` → `track_logger.py` → `ble_client.py` → `main.py`.
4. Провести юнит-проверку парсера на тестовой строке из раздела 2 (без BLE).
5. Запустить `main.py` при включённом ESP32-S3.
6. Зафиксировать результат.

## 6. Критерии приёмки

- [ ] `pip install -r requirements.txt` без ошибок.
- [ ] Парсер корректно извлекает координаты из тестовой строки: `lat=48.117300`, `lon=11.516667`.
- [ ] Приложение подключается к устройству по MAC.
- [ ] Чанки склеиваются в полные NMEA-строки без потерь.
- [ ] В консоли появляются строки `FIX` не реже 1 раз в 2 секунды.
- [ ] CSV-файл создаётся и пополняется.
- [ ] При выключении ESP32 приложение пишет `Disconnected`, переподключается после включения.
- [ ] Ctrl+C завершает работу без traceback.

## 7. Ограничения

- Не модифицировать прошивку ESP32.
- Не использовать внешние NMEA-библиотеки.
- Не запрашивать pairing/bonding.
- Пути только относительные внутри каталога проекта.
